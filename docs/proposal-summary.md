# CapstoneFlow Proposal Summary

## Problem

Capstone work is spread across requirements, user stories, weekly reports, repository artifacts, feedback, and checkpoint deliverables. A project can appear to be progressing while required evidence or review items remain incomplete. CapstoneFlow will test whether a requirement-to-evidence workflow can make missing work easier to identify.

## Proposed solution

CapstoneFlow is a small web application with student and reviewer workspaces. Students maintain project scope, requirements, weekly reports, evidence links, and responses to feedback. Assigned reviewers inspect the same project records and leave item-specific feedback. The application calculates an explained readiness summary from configured rules; it does not grade work or replace instructor judgment.

## Measurable objectives

1. Trace all 12 baseline stories to checkpoints, acceptance criteria, and test evidence.
2. Verify readiness rules using planned rule tests.
3. Evaluate whether users can complete the core workflow without assistance.
4. Compare weekly-report preparation time against the documented existing process.
5. Verify protected access, stability, and common-page response-time targets.

## Scope

Included: project records, student/reviewer roles, four checkpoint types, 12 baseline stories, weekly status history, feedback, evidence links, readiness summaries, authentication, and authorization.

Excluded: official grading, LMS submission, university SSO, GitHub API synchronization, automated evidence-quality assessment, email notifications, mobile apps, large-file storage, and high-volume scaling.
